## Profile 与 Bundle 的分工

一个运行中的 `dsh` 是**启动时由若干有序层组合出的插件树**。这句话里的每个词都重要：不是一个固定的应用，也不是一份静态配置，而是「有序层的叠加结果」。

<Split>
  <Panel title="Profile：一个命名的组合" tone="accent">
    存放在 Harness home 里。它做三件事：

    - 列出它要叠加的 bundle（**有序**）
    - 容纳它安装的树外插件
    - 保存用户自己的 `cordis.patch.yml`

    `web`、`headless`、`sdk`、`sdk-minimal`、`acp` 作为模板随产品发布。
  </Panel>
  <Panel title="Bundle：配置行的分发格式" tone="violet">
    它分发的是 **Cordis 配置行 + 这些行要挂载的代码**。

    关键性质：bundle 插入的内容<strong>仍然可以被它上面的层 patch</strong>。这就是为什么 bundle 不是「黑盒依赖」。
  </Panel>
</Split>

两者都在自己的 `package.json` 里用 `dsh` 字段声明身份：

```json
{
  "name": "@deepseek-ai/dsh-web-app",
  "dsh": {
    "bundle": "cordis.patch.yml"
  }
}
```

## 看清你这台机器实际启动的树

不要靠猜。有一个命令直接把组合结果打印出来：

```sh
dsh --profile web --dump-config
```

<Callout variant="key">
  它打印出来的<strong>任何一行</strong>，都可以被你自己的 patch 替换掉。这就是「不改一行源码改变产品行为」的完整含义。
</Callout>

## 写自己的 patch

patch 的两种操作只有替换与插入，没有「合并」。理解这一点能避免大量困惑。

```yaml
# my.patch.yml
patches:
  # 按 id 定位已有行，替换它的整个 config
  - id: tool-bash
    config:
      timeoutMs: 30000
      # 注意：这是整体替换。原来的其他字段不会被保留。

  # 插入新行
  - insert:
      name: my-local-plugin
      config:
        verbose: true
```

<Callout variant="rule" title="不要在插件里硬编码可调参数">
  会随部署变化的选择必须是经过校验的 <code>Config</code> 字段，能从 cordis.yml 改。
  一个 <code>DEFAULT_*</code> 常量或者测试钩子<strong>不算</strong>可配置性。
  协议常量、外部规范与安全不变量则保持固定，不应当暴露为配置。
</Callout>

<Callout variant="trap" title="默认值不是「run() 里的 ?? 兜底」">
  包边界上要求显式优于隐式：定默认值是拥有该实现里一个显式的{' '}
  <code>resolve(request): Spec</code> 步骤，而不是藏在 <code>run()</code> 内部的{' '}
  <code>?? default</code>。<code>dsh-shell</code> 的 request / spec 拆分是这条规则的模板，见
  <a href="/docs/execution">第 11 章</a>。
</Callout>

## 一个 session 想要不同的能力集合

如果需求是「让某一个会话拥有和别人不同的工具集」，答案不是 patch，而是**agent preset**：

```text
packages/preset/  per-session agent composition from preset cordis.yml files
```

preset 里的一行**服务**需要 `isolate` realm——否则它会和主树上的同名服务冲突。这是 preset 与普通 patch 最容易踩的差别。
