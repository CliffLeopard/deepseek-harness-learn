## 一句话定位

DeepSeek Harness 是一个 **agent harness**：它不是模型，也不是某个具体工具，而是把「模型 + 工具 + 会话 + 策略 + 界面」组装成一个可运行产品的那层骨架。它的命令行名字是 `dsh`。

它最重要的一条设计前提是：**没有一个特权内核**。模型适配器、工具注册表、会话日志、乃至 agent 主循环本身，都只是插件。扩展 `dsh` 的方式不是打补丁改内核，而是在其他插件旁边再挂一个插件。

<Callout variant="key">
  "Every part of the product is a plugin, including the model adapter, the tool registry, the
  session log, and the agent loop itself, so each is replaceable from configuration."
  —— <code>docs/architecture.md</code>
</Callout>

## 应用形态：同一棵树，五个出口

`dsh` 只有一个可执行入口。所有受支持的应用都是「`dsh` + 一个 profile 名」，这是一条被脚本强制检查的规则，而不是建议。

  head={['启动命令', 'profile', '形态', 'patch 重载']}
  rows={[
    ['dsh web', 'web', '浏览器 GUI（--profile web 的官方别名）', '实时重载'],
    ['dsh --profile headless', 'headless', '一次性任务运行器，无服务器', '启动时一次性应用'],
    ['dsh --profile sdk', 'sdk', 'SDK 的 JSON-RPC 服务端', '启动时一次性应用'],
    ['dsh --profile sdk-minimal', 'sdk-minimal', '独立最小 SDK 树，不叠加 dsh-base', '启动时一次性应用'],
    ['dsh --profile acp', 'acp', '仅自动化用途的 ACP 服务端', '启动时一次性应用'],
  ]}
/>

<Callout variant="rule" title="应用启动规则">
  vendored CLI、仅用于构建或测试的可执行文件、进程内直接挂载插件、以及私有的浏览器 WebWorker 预览，<strong>都不是</strong> Harness 的应用启动器。<code>scripts/verify-application-entrypoints.ts</code>
  会把每个包的 bin、可执行源文件与根目录 demo 归入明确的类别，并拒绝任何绕过 `dsh` 的 Node 应用路径。
</Callout>

自定义组合的边界也由此确定：调用方能选择的是 **profile 名 + 有序的 patch 文件**，而不是一整棵 Cordis 树。Python SDK 与 TypeScript SDK 都遵守同一条约束。

## 三个事件域，以及为什么先选域

绝大多数改动的第一个决定不是「写在哪个文件」，而是「用哪个事件域」。选错域会让功能在重载后消失，或者让循环耦合上某个策略。
