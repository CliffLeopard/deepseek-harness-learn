## 插件是贡献，不是内核补丁

`dsh` 没有特权内核。你要加的东西——工具、策略、提示段落、适配器、UI——都写成一个插件，再挂进那棵已经在跑的树。

这一章只回答两件事：

1. **怎么写**一个会被 Cordis 挂上的模块。
2. **它怎样进入一次 turn**：从 `cordis.yml` 的一行，到模型看见的工具、被拦住的调用、或写进日志的事件。

<Callout variant="key">
  新行为挂在已经写明的扩展点上。不要改 <code>agent-loop</code>。要改循环本身，必须同时改{' '}
  <code>docs/architecture.md</code> 里的扩展点地图。
</Callout>

## 三种包，三种进树方式

先分清你在写哪一种。名字都叫「插件」时，进树的路完全不同。

<DataTable
  head={['种类', '怎么进树', '怎么认']}
  rows={[
    ['plugin', 'cordis.yml / patch 里的一行：name 指向模块', '导出 apply，或默认导出一个 Service'],
    ['bundle', 'dsh plugin --profile web add 某个 bundle 包', 'package.json 里有 dsh.bundle.patch'],
    ['library', '只作为别的包的依赖', '没有 apply，也没有独立的安装命令'],
  ]}
/>

<Callout variant="trap" title="dsh plugin add 只激活 bundle">
  普通插件不会因为跑了这条命令就出现在树上。它必须作为{' '}
  <code>cordis.yml</code> 的一行被 Loader 挂上——写进某个 bundle、profile 的{' '}
  <code>cordis.patch.yml</code>，或命令行 <code>--patch</code>。
</Callout>

仓库里的例子：`packages/todo/tool-todo` 是 plugin（`export function apply`）；`packages/bundle/base` 是 bundle，它的 `cordis.patch.yml` 用一行把 `@deepseek-ai/dsh-tool-todo` 挂进去。

## 最小插件

Cordis 加载模块时，用当前的 `ctx` 调用 `apply`。你不写启动代码：插件只描述自己贡献什么，组合文件决定挂哪些。

```ts
import type { Context } from '@deepseek-ai/cordis'

export const name = 'hello'
export const inject = ['tools']

export function apply(ctx: Context) {
  ctx.tools.register(myTool)
}
```

另外两种写法在 [第 02 章](/docs/cordis)：带 `apply` 方法的对象，以及占据 `ctx` 上某个服务键的 `Service` 子类。在需要公开服务之前，用函数即可。

<Callout variant="warn" title="列表顺序不决定谁先跑">
  <code>cordis.yml</code> 里的行是并发启动的。先后由 <code>inject</code> 决定：你声明要等{' '}
  <code>tools</code>，就会等到 <code>ctx.tools</code> 出现才 apply。
</Callout>

<Callout variant="rule" title="加载失败要响，不能假装没这行">
  <code>apply</code> 抛错会让进程退出。模块路径或包名拼错时，Loader 记一条错误，不会默默跳过——看起来「挂了没效果」，先查拼写。
</Callout>

## 四种最常见的插件

### 1. 给模型用的工具

注册到 `ctx.tools`。schema 会自动进提示装配。

```ts
import type { Context } from '@deepseek-ai/cordis'
import { defineTool } from '@deepseek-ai/dsh-tools'

export const name = 'greet-tool'
export const inject = ['tools']

export function apply(ctx: Context) {
  ctx.tools.register(defineTool({
    name: 'greet',
    description: 'Greet someone by name.',
    parameters: {
      name: { type: 'string', required: true, description: 'The name to greet' },
    },
    output: {
      schema: { type: 'string' },
      render: (_args, value) => [{ type: 'text', text: value }],
    },
    async execute(args) {
      return `Hello, ${args.name}!`
    },
  }))
}
```

`defineTool` 会按 schema 校验模型传来的 JSON，再交给 `execute`。你返回的是规范值；`output.render` 再变成模型看见的内容。细节在 [第 08 章](/docs/tools) 和仓库 `docs/cookbook/adding-a-tool.md`。

本地试跑（必须走 `dsh` 加 profile，不能用包自己的 bin）：

```sh
pnpm dsh web --patch ./scratch-plugin/cordis.yml
```

对应的 patch 只需要一行，指向你的模块。

### 2. 钩子 / 策略

不注册新工具，只在已有管线上拦一把。waterfall **必须调用 `next()`**，否则整条链短路。emit / parallel / serial / bail 什么时候用，见 [第 02 章](/docs/cordis#事件派发模式)。

```ts
import type { Context } from '@deepseek-ai/cordis'
import type { PreToolDecision, ToolExecution } from '@deepseek-ai/dsh-tools'

export const name = 'permission-gate'

export function apply(ctx: Context) {
  ctx.on('tools/pre-execute', async (exec: ToolExecution, next): Promise<PreToolDecision> => {
    if (!(await isAllowed(exec))) {
      return { kind: 'deny', reason: 'Denied by policy.' }
    }
    return next()
  })
}

declare function isAllowed(exec: ToolExecution): Promise<boolean>
```

### 3. 提示段落与动态上下文

```ts
export const inject = ['systemPrompt']

export function apply(ctx: Context) {
  ctx.systemPrompt.section({
    name: 'my-guidance',
    order: 5100,
    text: 'Prefer the greet tool when the user asks for a hello.',
  })
}
```

稳定的指导写成 `PromptSection`（进系统提示前缀）。会变的事实写成 `PromptContext`，变成 user-role 快照，没变就不必重写。每个 step 重新装配，所以 scope 上的 shadowing 和 restriction 能在 turn 中途生效。见 [第 13 章](/docs/context)。

### 4. 界面或协议桥

听 `session/event` 画界面；人说的话用 `agent.followup()` 送回 inbox。不要自己存一份模型历史——历史从日志算出来。

浏览器里的 Web Client 另有一套：注册 `ConversationNodeDefinition` 和带 key 的 renderer，见 [第 14 章](/docs/web)。

<Callout variant="warn" title="裸插件名必须出现在解析它的 manifest 的 dependencies 里">
  Raw / Web 的 <code>cordis.yml</code> 里写的包名，要能被那份 resolver manifest 解析到。
