## 三个词，不能混用

  items={[

      term: 'round',
      sig: '包住 turn 的外层策略迭代',

    },

<Callout variant="trap" title="最常见的三个误解">
  **「一次对话就是一个 turn」**——不对。一个 turn 里可能有十几个 step。

  **「没有模型请求就没有 turn」**——不对。被拒绝的输入仍然会开启并关闭一个**不花费任何 step** 的持久 turn，好让日志记录下这次尝试。

  **「round 是 turn 的同义词」**——不对。round 是目标层的迭代，见 [第 12 章](/docs/orchestration)。
</Callout>

## turn 流程的文字提纲

这是 `docs/architecture.md` 里的提纲。先读它，再读下面的时序图。

```text
turn/start
  claim next-step input plus one queued message
  assemble prompt sections + tool schemas
  -> agent/pre-step                   reject | enter(messages, startsRequestSeries?)
     reject, or a first enter rewritten empty -> close the turn with no step
     step/start
     append entered messages as user/message
     derive model history from the log
     agent/request -> llm/stream -> assistant/chunk* -> assistant/message
     tool/call* -> tools/pre-execute -> tools/execute -> tools/post-execute -> tool/result*
     step/end
     tools owe another request, or next-step input arrived -> claim -> next step
  -> agent/turn-stopping
turn/end
```

## 哪些是持久事件，哪些是活的扩展点

这个区分决定了你的监听器在重载后还在不在。

<Callout variant="warn" title="waterfall 必须调用 next()">
  <code>agent/pre-step</code>、<code>agent/request</code>、<code>llm/stream</code> 与三个{' '}
  <code>tools/*</code> 都是 waterfall，监听器<strong>必须调用 next()</strong> 才能把控制权委托下去。
  <code>agent/turn-stopping</code> 是 serial，它<strong>没有</strong> next()。五种模式的对照见
  <a href="/docs/cordis#事件派发模式">第 02 章</a>。
</Callout>

## 错误恢复与压缩

`assistant/message` 事件会记录**每一次成功的 provider 调用**，包括没有内容的、以及以 `max-tokens` 结束的。空内容不进入消息历史，但持久事件仍保留 usage 与 `sourceEventSeqs`——后者精确列出对应的 `assistant/chunk` 事件，允许是显式的空列表。

## agent/turn-stopping：终止检查点

它只在**自然停止且 next-step inbox 为空**时触发。它是 serial 的，没有 `next()`，因此它的返回值直接决定 turn 是否真的结束——这是「让 agent 自己决定要不要再干一轮」的挂点。

  </Panel>
