## 对话的词汇

一段对话是若干 `Message`；一条消息是**类型化内容块**的数组。块的联合类型从 `ContentBlockMap` 展开。

<DefList
  items={[
    { term: 'TextBlock', sig: '{ text }', desc: '可见文本。' },
    { term: 'ReasoningBlock', sig: '思考内容', desc: '与可见文本明确区分。' },
    { term: 'ImageBlock', sig: '持久图片附件', desc: '指向 attachment seam 里的持久引用。' },
    { term: 'ToolCallBlock', sig: '{ id: ToolCallId, name, arguments }', desc: 'arguments 是原始 JSON 字符串。' },
    { term: 'ToolResultBlock', sig: '{ toolCallId, content: ContentBlock[], isError? }', desc: '内容是嵌套的块数组。' },
  ]}
/>

<Callout variant="rule" title="新增模态的门槛">
  只有当它的<strong>适配器、UI、压缩与持久回放</strong>四条路径都尊重它时，一个新模态才能进入这个可合并扩展的 map。
</Callout>

`Message` 是被投递、持久历史与模型请求**共享的同一个**不可变表示：

```ts
interface Message {
  /** Stable identity preserved across every representation boundary. */
  readonly id: MessageId
  /** Provider-neutral conversation role. */
  readonly role: 'system' | 'user' | 'assistant'
  /** Exact model-facing blocks. */
  readonly content: ContentBlock[]
  /** Required source fields supplied by the producer. */
  readonly source: MessageSource
}
```

## 两个独立的轴：谁产出的，和它是什么

这是这一层最精巧的设计，也最容易被误用。

<Callout variant="key">
  <code>MessageSource.kind</code> 回答<strong>「这是谁产出的」</strong>；<code>form</code>{' '}
  回答<strong>「这是什么类型的东西」</strong>。两个轴<strong>彼此独立</strong>——多个生产者可以共享一种 form，一个生产者也可以在一个会话里发出多种 form。
</Callout>

<Split>
  <Panel title="MessageSourceMap：谁产出的" tone="accent">
    可合并扩展的和类型，插件可以加自己的 `kind`。

    - `user`：`{ kind: 'user' }`
    - `plugin`：`{ kind: 'plugin', plugin: string }` & `ContextFormed`
    - `model`：`ModelMessageSource`
    - `tool`：`ToolMessageSource`
  </Panel>
  <Panel title="ContextForm：它是什么" tone="violet">
    这个词只描述信息类型，**不描述怎么画**。颜色、图标、排序、默认折叠都是消费者的事，不允许进入这个联合。

    - `instructions`：从工作区文件里读出、模型应当遵循的指令
    - `catalog`：本会话可用项的目录，随变化重新发布
    - `snapshot`：当前状态，同一生产者更晚的快照取代更早的
    - `notice`：刚刚发生的一次性说明，不取代任何东西
    - `relay`：另一个 agent 发给这一个的消息
    - `recall`：从另一个会话日志里提取的材料，进入时可能已被缩减
  </Panel>
</Split>

`ContextFormed` 用 `form` 做判别，因此**生产者无法在不提供该 form 所需字段的情况下选择这个 form**：`notice` 必须记录它的一行说明 `summary`，`snapshot` 必须记录它的 `sections`。省略 `form` 仍然合法——未声明的上下文就是有文档的默认值。

## StreamChunk：原始流式协议

一个流式响应会**交错**若干类型化块（文本、推理、多个工具调用）。`index` 把每个 delta 绑到它的块上；`block-end` 携带**已完整组装**的 `ContentBlock`，这样消费者不必自己重新组装 delta。

```ts
type StreamChunk =
  | { type: 'block-start'; index: number; blockType: ContentBlockType }
  | { type: 'text-delta'; index: number; text: string }
  | { type: 'reasoning-delta'; index: number; text: string }
  | { type: 'tool-call-delta'; index: number; id: ToolCallId; name?: string; argumentsDelta: string }
  | { type: 'block-end'; index: number; block: ContentBlock }
  | { type: 'usage'; usage: TokenUsage }
  | { type: 'finish'; reason: FinishReason; replayState?: ReplayEnvelope }
```

<Callout variant="warn" title="它是封闭联合，switch 必须以 assertNever 结尾">
  加一个变体会在<strong>每一个必须处理它的消费者</strong>处打断编译——这正是想要的效果。
  这与 <code>SessionEventMap</code>（可合并扩展、必须走 default）恰好相反，不要混淆两者。
</Callout>

## LlmFailure：可序列化的失败事实

```ts
/** Serializable provider or transport failure facts; policy decides whether they are retryable. */
interface LlmFailure {
  readonly message: string
  /** Stable provider-neutral machine-routing code. */
  readonly code: string
  readonly status?: number
  /** Provider-requested delay in milliseconds, when valid and available. */
  readonly providerRetryAfterMs?: number
  readonly requestId?: ProviderRequestId
}
```

<Callout variant="note">
  <code>providerRetryAfterMs</code> 是<strong>provider 请求的一个经校验的正延迟，不是一个重试决策</strong>。
  决策属于策略层。
</Callout>

## 请求信封与可重建性

循环从**已记下的状态**构建每个请求。`EpochHeader` 记录调用配置、标记由适配器默认值提供的字段，并通过完整的 `request/header` 快照记下渲染后的提示与**真正返回给模型的工具顺序**（由 `toolOrder` 配置，未设置时按字典序）。

<Callout variant="rule" title="模型可见 ⟺ 已记录，在这里体现为一条纯函数">
  信封 + 从日志算出的消息 ⇒ <strong>请求可以从会话日志重建</strong>。这也是为什么加一种模型看得见的输入必须先加一个会话事件。
</Callout>
