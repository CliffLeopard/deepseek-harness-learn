## 一条仅追加的日志

一个 `Session` 是一条**仅追加**的 `SessionEvent` 日志——它是一个 agent 整段交互历史的**唯一真相**。

<Callout variant="key">
  LLM 消息历史是从日志<strong>算出来</strong>的，从不单独存储；回放就是用同一批事件再算一遍。
</Callout>

日志本身的持久化（持久化 seam、后端、崩溃恢复）是**另一个**关注点：`ctx.sessions` 只管内存里的事件溯源模型。

## session/end-seed：种子与活写入的分界

带显式种子构造的 Session（restore、fork 或 replay）会在种子之后立刻追加这条**仅日志**事件，作为它的第一次活写入。

<Callout variant="key">
  它存在的理由是：<strong>种子历史与活的工作在字节上完全一样</strong>。这会让任何拥有独立开闭括号的插件失效——一个未配对的{' '}
  <code>compaction/start</code>，无论写入方是崩在压缩中间、还是正在压缩，读起来都一样。
  在 <code>session/end-seed</code> <strong>之前</strong>的开启标记来自构造种子，属于一个已经结束的生命周期。
</Callout>

要**定位最后一条** `session/end-seed`，而不是假设它出现在 `firstLiveSeq`：已经以它结尾的种子不会被重复标记，所以重新打开一个未被改动的会话不会让日志每次都增长。

<Callout variant="warn" title="它不是关于其他写入方的活性信号">
  一个并发存活的会话会把自己的边界放在别处，所以要容忍并发写入方，需要日志之外的活性信号。
</Callout>

## projection seam

`dsh-session-projection` 拥有 `ctx.sessionProjections`：注册的单元**增量地**折叠已提交事件，Host 消费者通过 `stateOf()` 读一个类型化状态，carrier 通过 `snapshot()` 批量下发裁剪后的客户端视图。

<Callout variant="trap" title="不允许静默兜底">
  Host 读取方要么在激活时<strong>要求</strong>这个服务，要么在注册表或必需 key 缺失时<strong>显式失败</strong>。
  贡献方可以保留 <code>ctx.inject(['sessionProjections'], ...)</code> 式的注册，但不能给缺失的 host 值悄悄设默认。
</Callout>

agent-loop 为它的读取方注册共享的 `turnBoundary` 状态。`ctx.sessionProjectionCache` 则按会话**持久地记下** projection 单元状态（限流 + `turn/end`/detach 强制点），并提供冷读阶梯：缓存行 + 持久化尾部回放——这样列表页永远不需要加载完整日志。
