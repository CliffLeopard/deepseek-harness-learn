## Subagent：两类能力，两种发现方式

这是这一层最容易搞错的地方。

<Split>
  <Panel title="启动期能力：静态描述符 + 标志位" tone="accent">
    provider 在一个静态描述符上标明它的**启动期**能力，服务在 one-shot 运行**存在之前**就检查。

    ```ts
    interface SubagentCapabilities {
      readonly agentOptions: boolean
      readonly outputSchema: boolean
      readonly depthLimit: boolean
      readonly toolFilter: boolean
      readonly persona: boolean
    }
    ```

    每个标志位与一个 `SubagentStartRequest` 选项**一一对应**（`depthLimit` 对应 `maxDepth`，其余同名）。
  </Panel>
  <Panel title="可续跑能力：方法存在即能力" tone="violet">
    可续跑的子 agent 由**续跑管理器自己**组装，所以靠一个可选方法拦住——

    `SubagentProvider.prepareContinuable`

    **方法的存在本身就是能力**，发现机制是 TypeScript 的类型收窄。
  </Panel>
</Split>

<Callout variant="warn" title="缺能力就直接拒绝，不能「接受后再假装没有」">
  需要 provider 不具备的能力的请求会被 <code>SubagentError('UNSUPPORTED_CAPABILITY')</code>{' '}
  拒绝。同样地，在没有 <code>prepareContinuable</code> 的 provider 上启动可续跑子 agent 也会被拒绝。
</Callout>

## Activation：可续跑子 agent 的核心概念

一个**可续跑的后台 subagent** 是**一个持久的子 Session**，加上**至多一个进程本地的 Activation**——也就是重建出来的子 Agent 还活着的那段时间。

<Callout variant="trap" title="Activation 不是请求、结果、取消，也不是 Task">
  它可以执行<strong>很多个 FIFO turn</strong>，并且在它创建的后代仍在运行时自己也继续活着。
  <strong>没有任何可续跑路径会创建 Task 或中间的结果包装器。</strong>
</Callout>

```text
persisted Session
  -> optional live Activation
       -> one retained AgentHandle
       -> Agent inbox as the only turn FIFO
       -> zero or more owned child Activations
```

## sendMessage：唯一的模型撰写消息操作

<Callout variant="key" title="Agent inbox 是唯一的队列">
  每一条 Agent 间消息都用 <code>Agent.steer()</code>：空闲目标会开一个 turn，运行中的目标在最近的 step 边界 claim 它。
  <strong>续跑层没有定义任何 subagent 专属的投递路由。</strong>
</Callout>

权限来自**确切的活发送方**：

每条被接受的消息被框成 `Agent <sender-id> sent a message:` 并记录 `AgentMessageSource`（`kind: 'agent-message'`，`form: 'relay'`）。

<Callout variant="warn" title="来源记录发送方，但不授予权限">
  provenance 只是记录。同样地，对 <code>startContinuable()</code> 与 <code>sendMessage()</code>，
  <strong>调用方 signal 只负责查找、把目标拉起来、以及把消息送进 inbox 被接受之前的这一段</strong>；
  之后管理器独立拥有这个 Activation——后来的调用方取消<strong>既不会</strong>取消已接受的 turn，
  <strong>也不会</strong> dispose 这个子 agent。
</Callout>

## interrupt：唯一的公开停止手段

`SubagentRuntime.interrupt(targetSessionId, authority)` **同步授权**，对活目标发出 `Agent.cancel(cause, { keepInbox: true })`，然后**不等待静止就返回**。

<DataTable

    ['当前 turn 被取消', 'Activation 本身'],
    ['已 claim 进被中断 turn 的工作不会被重新排队', '未被 claim 的挂起 inbox 工作'],

一旦被中断的驱动空闲下来，一次唤醒性的 send 就会**恢复那条被停放的 FIFO 队列**。

```ts
/**
 * Authority under which one interrupt request is admitted.
 */
type SubagentInterruptAuthority =
  | { readonly kind: 'user'; readonly parentSessionId: SessionId }
  | { readonly kind: 'ancestor'; readonly agent: Agent }
```

<Callout variant="note" title="不存在的目标是被接受的 no-op">
  未知、one-shot、或已 settled 的目标，以及一个没有管理器的组合，都是<strong>被接受的空操作</strong>。
  但对一个活目标，父地址不匹配或调用方在它的活祖先链之外会以 <code>UNAUTHORIZED</code> 拒绝。
</Callout>

## 持久枚举：不加载任何 Agent

`listChildren(parentSessionId)` 从 `ctx.sessions.list()` 与可选的 `ctx.sessionPersistence.list()` 的**活优先合并**中枚举直接子 agent——身份以会话为准——**不用查询服务，也不加载或恢复任何 Agent**。

<Callout variant="trap" title="origin: 'subagent' 标记不能建立身份">
  这个标记只用于<strong>分类枚举</strong>与粗粒度的通用路由拒绝。它<strong>不能</strong>建立有效的描述符、可恢复性或授权——
  身份归 projection 折叠所有，恢复归 Activation 契约所有。
</Callout>

每行的 `mode` / `label` 走一个**三级阶梯**：活子 agent 用 `stateOf()`（零次日志读取）；冷的用可选的 projection 检查点缓存（`cachedSnapshot`——自有描述符一旦追加就不可变，所以通过自有后缀 seq 核对过的身份已经是终态）；否则读一次 `persistence.inspect()` 并通过注册表折叠。

## Workflow：模型写的脚本

<Callout variant="rule" title="meta 与 args 是纯 JSON 数据">
  引擎在<strong>任何东西运行之前</strong>就用它的 schema 校验 <code>meta</code> 并直接拒绝——
  <strong>不会为了拿到 meta 而先求值任何脚本文本</strong>。
</Callout>

`parent` 是**必需**的：脚本启动的每一个子 agent 都归属于它，cwd、血缘与深度都通过 subagent seam 传递。`phases` 只是**进度用词**：`phase()` 调用为观察者匹配标题，不暗示任何执行结构。

## Ralph：一条建立在两个能力之上的专门策略

<Callout variant="warn" title="agent 循环里没有 Ralph 模式">
  <code>ralph</code> 是一个<strong>固定的前台 workflow</strong>：把一个不可变的目标交给一串<strong>全新的</strong>子 agent，
  每个都以<strong>没有对话种子</strong>开始，只携带上一份有界的报告。同会话的 goal 域保持独立。
</Callout>

调用在 worker 报告完成、报告一个具体阻塞点，或到达轮次上限时返回。部署默认 <code>maxRounds</code> 是 <strong>256</strong>；模型可以传一个更低的值，不能抬高。终止状态是封闭的：<code>complete</code> / <code>blocked</code> / <code>budget-limited</code> / <code>round-failed</code>。

<Callout variant="trap" title="完成与阻塞是 worker 的报告，不是独立认证">
  只在<strong>直接的人类明确要求</strong> Ralph 循环或全新 agent 的迭代执行时才用它。
  普通的长期目标属于 goal 工具；有界的委派属于 subagent 或 workflow。
</Callout>

## Goal：round 是外层策略迭代

  <strong>round</strong> 是<strong>包住 turn 的外层策略迭代</strong>，由续跑消费者拥有。
</Callout>
