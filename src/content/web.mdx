## 浏览器里的另一棵 Cordis 树

<Callout variant="key">
  Web Client <strong>本身就是一个浏览器侧的 Cordis 应用</strong>，由独立加载的插件装配而成。
  它不是「一个前端」，而是同一套插件哲学的第二次实例化。
</Callout>

它的架构有四块可复用的基础：**Client Modules** 加载插件图，**API Gateway** 提供类型化的 Host 通信，**Slots** 组合 React UI，**Conversation** 把一段会话历史窗口变成由目标拥有的视图。

<Callout variant="warn" title="产品 GUI 不用 Tailwind">
  <code>dsh web</code> 的样式是 CSS Modules、<code>clsx</code> 与 <code>--dsw-*</code> token，由{' '}
  <code>packages/client/ui-theme</code> 拥有。组件库与 Tailwind 在那棵 Client 树里是禁止的。本站（
  <code>learn/</code>）用 Next.js + Tailwind 讲架构，不等于产品 GUI 的技术选型。
</Callout>

内部的 `$events` 逻辑流是**连接 generation 的来源**。它开场的 `ready` 帧携带用于路径显示的 Host home，并在 **Host 监听器已挂上之后、任何 controller 开始基线读取之前**建立 generation。

## 写一个可回放的事件族

<Callout variant="rule" title="先定一个稳定的业务 id，再写 Definition">
  每一个贡献到同一个 Node 的事件都必须携带那个 id，或从它自己的载荷独立算出来。
  <strong>客户端不能把一个 update 分给「最近那个未完成的」Context。</strong>
</Callout>

<DataTable
  head={['事件', '角色', '必需的持久事实']}
  rows={[
    ['review/start', '唯一的 start', 'reviewId · Turn/Step 坐标 · title'],
    ['review/progress', 'update', '同一个 reviewId · 坐标 · 可回放的进度'],
    ['review/end', 'update', '同一个 reviewId · 坐标 · 最终摘要'],
  ]}
/>

每个 `(kind, id)` **最多有一个 start 事件**。单事件的业务可以用事件自身的稳定身份（如 `event.seq`）作为它 Definition 本地的 id。

<Callout variant="trap" title="增量事件被支持，但要优先整值检查点">
  因为当 start 落在已加载窗口<strong>之外</strong>时，整值检查点仍然有用。
  每个 delta 必须携带稳定 id，并在按日志 <code>seq</code> 升序回放时产生<strong>确定性</strong>的 State——
  <strong>它不得依赖只在活运行期存在的内存</strong>。
</Callout>

如果当前历史窗口里只有 update，装配器会保留一个 pending Context 且**不构建 State**，直到更老的一页提供 start。如果产品必须在 start 加载之前就渲染，那么一个终态或检查点事件必须携带足够的整体回退状态——**不要靠扫描不相关的事件去恢复它**。

历史上连续的同块 `assistant/chunk` delta 会以 `chunkrow/text-chunks`、`chunkrow/reasoning-chunks` 或 `chunkrow/tool-call-chunks` 到达。它们的顶层 `seq` 与 `time` 标识第一个逻辑成员。这些**仅客户端**事件只能是 update；`start()` 收到的一定是标准 `SessionEvent`。

## 组件收到什么，以及收不到什么

<Callout variant="warn" title="组件收不到 ctx">
  父拥有的时点值通过 <code>renderSlot</code> 的 owner 参数进入；共享视图状态用一个声明的 store；
  <strong>服务与 model 对象留在 apply 闭包里</strong>，再通过回调或 observable 源交给组件。
</Callout>

<DataTable
  head={['输入', '由什么声明', '组件类型']}

    ['本地化的 t 函数', '注册的 locale 命名空间', 'PropsLocale<N>'],
    ['被选中的 chain 值', 'select 的结果', "ComposedProps 里的 matched"],
  ]}

<Callout variant="key" title="选择哪种输入的判据">
  已在某次渲染时点已知的值用 <strong>owner props</strong>；某一个条目的回调与私有 observable 用<strong>注册 inject</strong>；
  由 slot owner 控制的能力用 <strong>slot 级 inject</strong>；跨条目共享或跨重挂载保留的可变视图状态用<strong>声明的 store</strong>。
  <strong>React 节点通过子 slot 组合，而不是通过被注入的值。</strong>
</Callout>

`inject` 返回值里有一个保留的 `hooks` 对象，接受裸的 `getSnapshot` / `subscribe` 源。渲染器把 `hooks: { status }` 转成组件 prop `useStatus(selector)`，并按源身份缓存这个绑定——**组件拿不到源本身，也不直接调 `useSyncExternalStore`**。

## HTTP 载体

<Callout variant="note" title="dsh-host-webserver 不认识任何 harness 概念">
  它<strong>不是 agent 循环的一部分，也不是能力 seam</strong>：一个 <code>node:http</code> 插件，提供{' '}
  <code>ctx.webServer</code>、一个命名路由注册表、可选的 gzip 响应压缩、index.html 变换回调，以及一个插件可以认领的 fallback handler。
</Callout>

**每一个特性路由都由另一个插件注册**，包括 `/api` 桥、插件 bundle 与 HMR 事件流。它只服务浏览器：Electron 通过 `file://` 加载构建产物，并把 fetch 请求经 IPC 桥发送，而不走这个服务器。

`ctx.clientModules` 则是同一件事的四个面：扫描 host Loader 的条目找出声明了 `dsh.client` 的包、组合 `window.__DSH_BOOT__` 的条目图、在 `/plugins` 下提供带版本的 combo 脚本，以及回答每一次 index 注入收集。它是 web GUI 栈的**可选能力**，并且是 `dsh-host-webserver` 的**消费者**——载体提供前缀路由与它所回答的 `webserver/index-inject` 事件。
